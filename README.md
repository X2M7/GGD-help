# GGD-help

**V0.1.1 · Windows x64 鹅鸭杀透明会议蒙版。** 基于 [snapea/goose-duck-help](https://github.com/snapea/goose-duck-help) 改进，保留原项目作者归属。原项目的截图背景改成透明置顶窗口，可以直接看见后面的游戏会议人物，在旁边记录身份、发言线索和死亡情况。

项目仓库：[X2M7/GGD-help](https://github.com/X2M7/GGD-help)。

## 直接启动

从 [V0.1.1 Releases](https://github.com/X2M7/GGD-help/releases/tag/V0.1.1) 下载 **GGD-help-V0.1.1-win-x64.exe**，直接双击运行。发布包为单文件便携版，不需要安装 Node.js，也不需要另外下载 Electron 文件。首次打开需要解包到临时目录，可能稍慢。旧版 [V0.1.0](https://github.com/X2M7/GGD-help/releases/tag/V0.1.0) 保留在历史 Release 中。

本地源码目录中也可以双击 **启动助手.cmd**。已构建目录版时会启动：

```text
out\GGD-help-win32-x64\GGD-help.exe
```

这个本地目录版需要保留整个 `GGD-help-win32-x64` 文件夹；Release 中的单文件便携版则只需保留下载的 exe。

游戏请使用**无边框窗口或窗口模式**。独占全屏可能把桌面蒙版遮住。助手覆盖你选择的显示器；普通窗口没有自动跟随游戏窗口功能，需要用位置校准对齐。

## 游戏中使用

1. 启动后，屏幕上会出现 16 张小记录卡和右上方的悬浮开关。卡片之外的背景透明，不再需要截图。
2. **拖动悬浮开关左侧的六点手柄**可以移动它；点击「收起蒙版 / 显示蒙版」开关记录卡。隐藏不会清空记录。
3. 在会议发言轮中，把记录卡对齐对应人物。V0.1.1 移除了卡片的编号和昵称行，直接查看后面的游戏原昵称；每人有「好 / 中 / 坏」三个独立身份下拉框，可以同时保留不同阵营的身份推测。下面两个文字框分别用于「备注 1」和「备注 2」，修改后自动保存。
4. 用顶部的「第几轮」与加减按钮手动切换会议轮次。点击人物下方的死亡方式，记录为当轮死亡。
5. 需要继续操作游戏时，点击「穿透游戏」或悬浮开关的「穿透」。此时记录仍可见，鼠标操作交给游戏；点击悬浮开关的「编辑」恢复记录。点击「收起」则隐藏整个蒙版。
6. 下一局点击「新对局」并确认，清空本局记录，保留屏幕校准。

| 每人按钮 | 记录方式 |
| --- | --- |
| 刀 | 刀杀 |
| 票 | 投票出局 |
| 刺 | 刺杀 |
| 炸 | 炸死 |
| 吞 | 吞食 |
| 连 | 连带死亡 |
| ？ | 死因不明 |
| 复活 | 清除死亡标记，保留三个身份推测和两条备注 |

死亡后显示「第 N 轮 · 死亡方式」。可以直接改卡片中的轮次，也可点击其他方式更正死因；推进会议轮次不会改动已有死亡记录。未死亡时也可以先填写轮次，再点死亡方式进行补记。

身份选项沿用原项目并去重，分别放在好人（鹅）、中立、坏人（鸭）三个下拉框中；三个选择互不覆盖，未列出的身份可以写在任一备注框里。所有信息均由玩家手动记录，助手不会自动识别人物、死亡或会议轮次，也不会读取游戏昵称。

## 分辨率与位置

打开「位置 / 设置」：

- **游戏所在显示器**：选择游戏屏幕，显示估算分辨率和 Windows 缩放。非整数缩放下，系统坐标取整可能使显示值相差 1–2 像素。插拔显示器或更改分辨率时重新适配。
- **布局预设**：提供 1280×720、1366×768、1600×900、1920×1080、2560×1440、3840×2160、1920×1200、2560×1600、2560×1080、3440×1440。
- **游戏画面比例**：宽屏上游戏如果两边有黑边，选择游戏实际比例，如 16:9。游戏铺满整个屏幕时可选「铺满屏幕」。两个超宽预设使用各自准确的宽高比。
- **整体左右 / 上下、位置间距**：整体对齐会议人物区域。预设只更改布局参考比例，不修改系统或游戏分辨率。
- **拖动校准角色位置**：启用后，拖动每张卡片的「⠿」到对应人物旁。按 Esc 完成。可以避开头像和发言标识，透过空白直接观察人物。
- **记录卡大小 / 底色**：调整按钮大小和卡片背景透明度。
- **显示人数**：隐藏末尾未使用的卡片，不删除其记录。人数、座位排列或游戏 UI 变化时，请重新逐人校准。

默认位置来自原项目的 1920×1080、4 列 × 4 行布局；使用比例坐标缩放，不保证不同游戏版本、人数或 UI 缩放下第一次就准确对齐。校准会按**显示器 ID、分辨率、Windows DPI 缩放**分别自动保存，切回对应屏幕配置会恢复位置。选择预设保留逐人校准；「重置当前位置」需确认，只重置当前屏幕。

## 快捷键和恢复

| 快捷键 | 功能 |
| --- | --- |
| Ctrl + Shift + G | 显示 / 隐藏蒙版 |
| Ctrl + Shift + L | 切换记录 / 鼠标穿透 |
| Esc（记录窗口内） | 关闭设置、退出校准或取消确认 |

悬浮开关的「⋯」菜单和系统托盘菜单可以切换显示器、找回开关并恢复编辑，以及退出程序。若快捷键被其他程序占用，悬浮开关会提示，仍可用鼠标操作。

编辑备注时键盘输入属于助手。回到游戏前使用「穿透」或「收起」，或者点击游戏的透明空白区域。重启助手会恢复为可见、可编辑状态，避免因上次隐藏而找不到窗口。

## 运行源码与构建

开发环境：Windows，Node.js 22.12+（本次使用 Node.js 24），npm。

```powershell
npm install
npm start
```

Electron 首次启动可能需要下载运行文件。开发依赖锁定在 `package-lock.json` 中；已有锁文件可使用 `npm ci` 安装。

```powershell
npm run check
npm test
npm run test:smoke
npm run package
npm run dist
npm run test:release
```

- `check`：主要脚本语法检查。
- `test`：死亡记录、比例布局、黑边、坐标反算、不同 DPI 配置和开关恢复的单元测试。
- `test:smoke`：启动真实 Electron 窗口，检查透明置顶、角色记录、死亡轮次、复活、拖动、开关和重启保存。使用独立临时配置；截图输出到 `artifacts`，不影响日常记录。
- `package`：生成 Windows x64 免安装目录，输出到 `out/GGD-help-win32-x64`。
- `dist`：生成 Release 单文件便携版，输出到 `release/GGD-help-V0.1.1-win-x64.exe`。
- `test:release`：构建后实际启动单文件 exe，使用独立测试配置验证发布程序。

## 文件与数据

- `index.js / preload.js`：透明窗口、悬浮开关、全局快捷键、显示器事件和受限 IPC。
- `launcher.html / launcher.js / launcher.css`：独立悬浮开关。
- `core.js`：角色状态和坐标计算；`renderer.js / index.html / style.css`：记录与校准界面。
- `shell-state.js`：开关位置校验；`tests`：逻辑及窗口测试。
- `legacy-data.js`：首次运行时迁移旧版记录，不覆盖已经存在的新配置。

记录、布局与偏好存储在 `%APPDATA%\GGD-help`。窗口位置写在 `overlay-window.json`，角色与校准存储在 Electron 的 localStorage 中。正常关闭、隐藏和重启均保留记录；「新对局」只清空角色记录。若界面提示保存失败，请先检查磁盘空间与配置目录权限。

从 V0.1.0 升级时，原先从列表选择的身份会移入对应的阵营下拉框，旧备注保留在「备注 1」中，「备注 2」初始为空。死亡记录和位置校准继续保留；旧的手填昵称仍保存在原记录中，界面不再显示或编辑。

若此前使用 `goose-duck-help-overlay`，**请先退出旧版，再启动新版**。首次运行 GGD-help 时会在新配置尚不存在的情况下，复制旧目录 `%APPDATA%\goose-duck-help-overlay` 中的窗口配置和 Local Storage。旧数据不会删除，新数据不会被覆盖；测试专用配置不会触发迁移。内部记录键保留旧名以兼容已有记录，界面和程序名称统一为 GGD-help。

迁移失败时原数据仍会保留，可手工恢复：先退出两个版本并备份 `%APPDATA%\GGD-help`，再将旧目录中的 `Local Storage` 文件夹与 `overlay-window.json` 复制到新配置目录。若新版本已有需要保留的记录，请先另存备份，再决定是否替换。

实现使用 Electron 的[透明窗口](https://www.electronjs.org/docs/latest/tutorial/custom-window-styles)、[鼠标穿透](https://www.electronjs.org/docs/latest/tutorial/custom-window-interactions)和[显示器 DIP 坐标](https://www.electronjs.org/docs/latest/api/screen)接口，不注入游戏进程。实际游戏中的首次位置对齐仍需由玩家完成。
